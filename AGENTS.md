# Repository Guidelines

Перед началом работы прочитайте README, `docs/development.md`, актуальные
правила в `CODESTYLE.md` и состояние Git. В этом репозитории навыки — исходные
материалы продукта: храните их только в `src/skills/<name>/`, не создавая копий
в `.agents/skills` или `.claude/skills`.

Каждый навык содержит английский `SKILL.md` с frontmatter Agent Skills. Имя
должно совпадать с именем каталога и быть в kebab-case; обязательная строка
`metadata.version` использует полный SemVer 2.0. Используйте `references/`,
`scripts/` и `assets/` только для материалов, которые нельзя кратко поместить
в основной файл. Ссылки из `SKILL.md` должны быть относительными и указывать
на существующие файлы.

Сначала выполняйте read-only анализ и проверки через Docker Compose. Сохраняйте
незакоммиченные изменения пользователя; не отменяйте их без явного запроса.
Для каждого изменённого русского Markdown-документа обновляйте английский
файл с суффиксом `_EN` и его `source-sha256`.

Перед подтверждением не выполняйте deploy или apply, миграции, удаление данных,
публикацию артефактов, перезапись истории Git и внешние изменения. Не храните в
Git реальные секреты: используйте безопасные примеры и переменные окружения.

После изменения навыка, валидатора или документации выполните применимые
Compose-команды из `docs/development.md`: `verify` проверяет контракт
репозитория, а `tests` выполняет его полностью. Не запускайте проверки напрямую
через Python на хосте и не документируйте несуществующие команды.
